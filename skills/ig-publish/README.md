# ig-publish: локальная очередь публикаций

Этап 2 из плана автоматизации. Здесь только очередь на диске и проверки без
сети. **Скрипт ничего не публикует и не может опубликовать:** в нём нет
HTTP-клиента, токенов, загрузки файлов, фоновых задач и повторов.

## Что где лежит

| что | где |
| --- | --- |
| скрипт | `skills/ig-publish/igqueue.py` |
| тесты | `skills/ig-publish/test_igqueue.py` |
| инструкция для Claude | `skills/ig-publish/SKILL.md` |
| очередь | `~/.claude/instagram/queue/`, вне Git-репозитория |

Одна публикация - одна папка:

```
~/.claude/instagram/queue/2026-10-12-seva-shepot/
    post.json      id, тип, статус, время, имена файлов, история
    caption.txt    подпись в UTF-8
    seva.mp4       медиафайл, копия
```

Нужен только Python 3.9 или новее. Сторонних пакетов нет.

## Команды

Запускать из папки `skills/ig-publish/` или указывать полный путь к скрипту.

```bash
python3 igqueue.py new --id 2026-10-12-seva-shepot --type reel --when "2026-10-12 19:00" --tz Europe/Moscow --caption-file ~/Desktop/caption.txt --media ~/Movies/seva.mp4
```

```bash
python3 igqueue.py check 2026-10-12-seva-shepot
```

```bash
python3 igqueue.py content 2026-10-12-seva-shepot
```

```bash
python3 igqueue.py validate 2026-10-12-seva-shepot
```

```bash
python3 igqueue.py list
```

```bash
python3 igqueue.py dry-run 2026-10-12-seva-shepot
```

| команда | что делает | пишет на диск |
| --- | --- | --- |
| `new` | создаёт папку черновика, копирует в неё подпись и медиа | да, только новую папку |
| `check` | структура `post.json`, обязательные поля, ID, дата, часовой пояс | нет |
| `content` | подпись и медиафайлы | нет |
| `validate` | всё вместе; если ошибок нет, `draft` становится `validated` | только `post.json` |
| `list` | таблица очереди | нет |
| `dry-run` | показывает, что было бы опубликовано | нет |

`check`, `content` и `validate` принимают `--all` вместо ID.

Другая папка очереди: `--queue ПУТЬ` перед командой или переменная
`IG_QUEUE_DIR`. Удобно для проб, чтобы не трогать настоящую очередь.

Код возврата: `0` - ошибок нет, `1` - проверка нашла ошибки, `2` - команда не
смогла выполниться (нет такой публикации, занятый ID, неверные аргументы).

## Черновик без медиа

`--media` и `--caption-file` необязательны. Без них создаётся черновик с пустой
подписью и пустым списком медиа, и проверка честно скажет, чего не хватает.
Чтобы добавить файл позже, положите его в папку публикации и впишите имя в
`post.json`:

```json
"media": ["seva.mp4"]
```

Оригинал файла `new` не трогает: в очередь попадает копия.

## Что проверяется

- **ID:** 3-64 знака, строчные латинские буквы, цифры и дефис; совпадает с
  именем папки; не повторяется в очереди.
- **Время:** `scheduled_at` в виде `2026-10-12T19:00`, без смещения и без `Z`;
  `timezone` - название пояса IANA, например `Europe/Moscow`. Несуществующее
  время (перевод часов) - ошибка. Прошедшее время - предупреждение.
- **Подпись:** не пустая, не длиннее 2200 знаков, не больше 30 хэштегов и 20
  упоминаний, без незаполненных `{{...}}`.
- **Медиа:** файл лежит в папке публикации, не пустой, не ссылка, с допустимым
  расширением и в пределах размера.

| тип | файлы | размер | как выходит |
| --- | --- | --- | --- |
| `reel` | один `.mp4` или `.mov` | до 300 МБ | через Instagram API, на будущем этапе |
| `photo` | один `.jpg` или `.jpeg` | до 8 МБ | вручную через Meta Business Suite |
| `carousel` | от 2 до 10 `.jpg`, `.jpeg`, `.mp4`, `.mov` | те же | вручную через Meta Business Suite |

## Статусы

`draft`, `validated`, `approved`, `published`, `failed`, `missed`, `cancelled`.

Сейчас работают только два перехода, оба делает `validate`:

- `draft` -> `validated`, когда все проверки пройдены. Вместе со статусом
  записываются SHA-256 подписи и каждого медиафайла.
- обратно в `draft`, если проверка нашла ошибку.

Если после проверки изменить подпись, файл или время, `list` и `dry-run`
покажут «изменено после проверки», пока `validate` не запущен заново.

Остальные статусы скрипт распознаёт и не трогает. Выставить их пока нечем.

## Подтверждение

Команды подтверждения нет: это отдельное действие, оно появится позже и будет
только вашим. Заранее сделано одно: подтверждение привязано к точному ID и к
хешам подписи, медиа, типа и времени. Если в `post.json` есть блок `approval`,
а содержимое с тех пор изменилось или ID не тот, `dry-run` покажет
«НЕДЕЙСТВИТЕЛЬНО», а `validate` снимет подтверждение, вернёт статус
`validated` и запишет это в историю публикации.

## Ограничения

- **Публикации нет.** Нет флага `--live`, нет сети, нет токенов, нет
  расписания. `dry-run` - единственный режим.
- **Содержимое медиа не проверяется.** Расширение `.mp4` не значит, что внутри
  подходящий кодек, длительность или пропорции. Проверка говорит только, что
  файл есть, не пустой и не слишком большой.
- **Длина подписи считается в знаках Python.** Instagram может считать эмодзи
  иначе; если подпись близка к лимиту и в ней есть эмодзи, будет предупреждение.
- **Время не контролируется.** Скрипт не следит за часами и не переводит
  публикацию в `missed`. Он только предупреждает, что время прошло.
- **Фото и карусели** лежат в очереди для порядка. Публикуете их вы.
- **Ничего не удаляется.** Убрать публикацию из очереди можно только руками.
- **Секретам здесь не место.** Не записывайте пароли и токены ни в
  `post.json`, ни в подпись.

## Тесты

```bash
cd ~/instagram-agent-skill/skills/ig-publish && python3 test_igqueue.py
```

Тесты работают во временной папке, не обращаются к сети и не трогают
настоящую очередь. «Видео» в них - несколько байт с расширением `.mp4`.
Отдельный тест проверяет, что скрипт не импортирует сетевые модули и не
запускает другие программы.
